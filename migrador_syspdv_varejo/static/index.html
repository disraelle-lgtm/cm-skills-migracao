Configuração do sistema onde o migrador está rodando.
Origem — SysPDV

Com instância, a porta é ignorada. O SQL Server é aberto só para leitura.

Firebird em Docker: use o caminho de dentro do container (ex.: /firebird/data/...).

Deixe o fbclient vazio: o migrador usa o client 64 bits da pasta windows\firebird_client_x64.

Destino — VarejoFacil (PostgreSQL)
O servidor vem de Conexões; aqui você escolhe o arquivo ou banco do SysPDV
O que é verificado no Firebird (nada é gravado no banco do SysPDV)
  • Cabeçalho: versão do Firebird e transações — avisa se o banco precisa de sweep (fica lento, não é corrupção).
  • Validação do próprio servidor Firebird, em modo somente leitura (como gfix -v -n): acha páginas e registros corrompidos; com o Firebird neste computador, mostra a página e a tabela ruins.
  • Leitura completa de cada tabela: mostra qual tabela está quebrada — é o que faria a migração parar no meio.

Backup (.GBK/.FBK): não dá para verificar sem restaurar — o migrador restaura num .FDB novo ao lado do backup (<nome>_RESTAURADO_<data>.FDB) e valida o restaurado, que já fica pronto para a migração.

container (opcional):

Automático: se houver um container do Firebird rodando e o arquivo estiver numa pasta compartilhada com ele, usa o Docker (traduz o caminho); senão, usa o Firebird instalado neste computador.

O que é verificado no SQL Server (nada é gravado no banco do SysPDV)
  • Banco: estado do banco (ONLINE/SUSPECT), DBCC CHECKDB (verificação oficial da Microsoft; precisa de usuário sysadmin ou db_owner) e páginas suspeitas registradas pelo SQL Server.
  • Arquivo .bak: de que banco e de quando é o backup, os arquivos dentro dele e a verificação do backup (RESTORE VERIFYONLY, com CHECKSUM quando o backup tiver).
  • Arquivos .MDF + .LDF (o banco físico): lê o cabeçalho do MDF sem anexar, anexa como banco temporário, roda o DBCC CHECKDB e desanexa no fim. Use uma cópia dos arquivos: ao anexar, o SQL Server pode atualizá-los para a versão dele.

Os caminhos são do servidor SQL Server — é ele quem lê os arquivos (o serviço do SQL Server precisa de acesso à pasta). O Procurar... mostra as pastas deste computador: use quando o SQL Server estiver nele.

  Regras da migração — são o padrão e valem sempre (Migração Inicial e Virada)
  

    

      
Geral

      
    
        
  • Registros com código zerado (00, 000, 000…) não são migrados.
    • 
        
  • Pode rodar de novo sem medo: o que já está igual no VarejoFácil fica "sem alteração" e nada é duplicado.
            Registro que já existe no VarejoFácil (mesmo CPF, mesma tributação, mesma programação de preço) é mantido.
    • 
        
  • "Não migrados" só aparece quando um registro deu erro ou foi pulado — o cartão do item mostra qual e o motivo.
    • 
        
  • Produto que não foi migrado (sem descrição, código zerado, fora de linha, erro…) é ignorado nas demais
            tabelas (código de barras, preço, estoque, custo…) — aparece como "pulado", com o motivo.
    • 
      

      
Cadastros padrão

      
    
        
  • Grupo e subgrupo só são migrados se a seção (e o grupo) existirem no SysPDV.
    • 
      

      
Pessoas

      
    
        
  • Funcionário: somente os ativos, vinculados à loja matriz como principal. Funcionário já cadastrado
            com o mesmo CPF não é duplicado.
    • 
        
  • Cliente: somente os que têm nome. O limite de crédito é sempre gravado com a espécie
            BOLETO RECEBER.
    • 
        
  • Fornecedor: somente os que têm CNPJ/CPF cadastrado.
    • 
      

      
Financeiro

      
    
        
  • Contas a receber: títulos em aberto ou pagos parcialmente, de clientes com nome. Juros e multa
            não são migrados.
    • 
        
  • Contas a pagar: títulos em aberto (sem data de pagamento e não excluídos) de fornecedores com CNPJ.
    • 
      

    

    

      
Produto

      
    
        
  • Produto sem descrição não é migrado. Produto fora de linha só entra com a opção
            "Incluir produtos fora de linha" marcada.
    • 
        
  • "Só com movimentação desde": marcada, migra apenas os produtos que tiveram venda, nota fiscal,
            movimentação de estoque ou cadastro da data escolhida (inclusive) até hoje. O filtro vale para todos os
            itens de produto e de estoque (preço, código de barras, impostos, fornecedor, saldos…).
    • 
        
  • Local de impressão: sempre 0 — o VarejoFácil não usa local de impressão.
    • 
        
  • Impostos federais: um de cada tipo por produto (PIS, COFINS, IRPJ, CSLL). Se o SysPDV tiver mais de um do
            mesmo tipo, fica o de menor código.
    • 
        
  • Código de barras: o que for igual ao código do produto não é migrado; o inválido vira LITERAL.
    • 
        
  • Encarte: somente encartes abertos ou programados.
    • 
      

      
Estoque

      
    
        
  • Saldo positivo e negativo vêm do SysPDV; os produtos sem saldo recebem automaticamente o movimento de saldo
            zero.
    • 
        
  • Produto que já tem saldo no VarejoFácil (ex.: virada, com vendas e inventários depois da migração inicial):
            é lançado um movimento de ajuste com a diferença para ficar igual ao SysPDV — nenhum movimento é apagado.
    • 
      

      
Final

      
    
        
  • Ao fim de toda migração a fila de sincronização do Panamá é atualizada. O formulário de validação
            fica no menu Relatórios depois da migração inicial.
    • 
      

    

  





  
Arquivos de troca de códigos — use as planilhas …_todos_…csv baixadas em Códigos (botão Download), depois do ajuste de códigos da migração inicial.

  
Como os arquivos de códigos são usados
    
    
  • Clientes: se na migração inicial houve troca de códigos de clientes, anexe o arquivo
        cod_novo_cod_antigo_cliente_todos_…csv. Cliente, limite de crédito e contas a receber passam a
        ser gravados pelo código novo. Cliente novo com código ≥ 999999 ganha o próximo código vago.
    • 
    
  • Produtos: se na migração inicial houve troca de códigos de produtos, anexe o arquivo
        cod_novo_cod_antigo_produto_todos_…csv. Produto, preço, EAN, estoque e os demais itens de
        produto passam a ser gravados pelo código novo. Produto novo com código EAN ganha o próximo código vago e
        válido, e o EAN vira código de barras; produto de balança mantém o código.
    • 
    
  • Sem arquivo: o item roda como na migração inicial (ex.: só os produtos tiveram troca? anexe só o
        arquivo de produtos).

Regras do ajuste de códigos
    
  
  • Clientes: cada código ≥ 999999 recebe o menor código livre (limite de crédito, contas a receber,
      cobranças e transações acompanham).
    • 
  
  • Produtos: cada código ≥ 999999 recebe um código livre de 10001 a 999998; o código antigo vira
      EAN do produto e a troca fica na alteração de produto do SPED. Produtos de balança ficam de fora.
    • 
  
  • Consultar mostra os códigos encontrados (nada é alterado). Ajustar códigos pede confirmação, faz a
      troca e mostra o código novo × antigo. Depois do ajuste, o botão Download no fim de cada linha baixa as
      planilhas (.csv): todos os códigos e só os alterados.
